# 两个内网节点通过公网节点中继

拓扑为 `A → R ← B`：A、B 主动建立到公网 R 的 UDP 连接，再通过 R 建立 A、B 之间的端到端会话。A、B 不需要开放入站端口。需要允许向 R 的 UDP 端口出站，并允许该连接的返回流量。

这是项目自定义 UDP 协议的单跳中继，不是标准 QUIC、TURN 或 libp2p 中继。三台节点都需要更新到支持中继的版本，并使用相同网络参数。地址中的 `p2p-circuit` 表示此项目的中继路径。

## 配置

在三台机器分别使用独立、持久化的 `system.path`。先启动节点，从带认证的 `GET /node/info` 获取各自 `peerId`；公网节点必须保留身份文件，重启时继续使用相同身份。

公网 R 的配置：

```yaml
system:
  p2p-bind-address: 0.0.0.0
  quic-port: 8334
  relay:
    server-enabled: true
    bytes-per-second: 2097152
```

开放 R 的 UDP 8334。A、B 也需要绑定可出站的网络接口，不能沿用本机调试用的 `127.0.0.1`；配置中填写 R 的真实公网 IP 和公钥：

```yaml
system:
  p2p-bind-address: 0.0.0.0
  relay:
    servers:
      - /ip4/PUBLIC_IP/quic/8334/p2p/RELAY_PEER_ID
```

A 再配置 B 的公钥，自动建立并维持 A ↔ B 会话：

```yaml
system:
  p2p-bind-address: 0.0.0.0
  relay:
    servers:
      - /ip4/PUBLIC_IP/quic/8334/p2p/RELAY_PEER_ID
    peers:
      - B_PEER_ID
```

只需一端配置对端 `peers`，建立后的会话可双向通信。公钥支持 `/node/info` 返回的 Base58 或 64 位十六进制。`PUBLIC_IP`、`RELAY_PEER_ID`、`B_PEER_ID` 为占位符，必须替换。也可使用 Spring Boot 命令行参数 `--system.relay.server-enabled=true`、`--system.relay.servers=地址`、`--system.relay.peers=公钥`。

`servers` 是本机信任的中继列表。两端都必须配置 R；仅在 A 指定地址不足以让 B 接受 R 投递的内层握手。中继只向已经与 R 建立认证直连的目标转发，不代替目标建立任意 UDP 连接。

## 手动连接和验证

已有中继配置时，管理员可调用 `POST /p2p/connect`，将 `addr` 参数 URL 编码为：

```text
/ip4/PUBLIC_IP/quic/8334/p2p/RELAY_PEER_ID/p2p-circuit/p2p/B_PEER_ID
```

手动连接不会加入自动恢复列表；需要持续恢复的对端应放入 `system.relay.peers`。

使用 `Authorization: Bearer 管理员令牌` 调用：

| 接口 | 验证内容 |
| --- | --- |
| `GET /p2p/relay/status` | 受信任的中继、内层会话目标、实际中继公钥、路径是否有效；R 的转发字节数与拒绝数 |
| `POST /p2p/probe?peerId=B_PEER_ID&bytes=1048576` | 向 B 发送 1 MiB 随机数据，校验 B 返回的 SHA-256 摘要；返回成功状态、字节数和耗时 |
| `GET /p2p/nodes` | 现有连接与流量诊断 |
| `GET /node/info` | 节点身份、区块高度与链尖 |

分别在 A 和 B 调用探测，确认两个方向都成功，且 `circuits` 指向对端、R 的 `forwardedBytes` 持续增长。探测耗时包括发送、重组和返回摘要，不代表纯网络 RTT 或带宽上限。探测限制为 1 字节至 1 MiB，本机最多同时执行两个；POST 需要管理员权限。

## 故障恢复与资源限制

- 现有心跳保持 NAT 映射。断开或过期的 R 会话使依赖它的内层会话失效；配置的 `servers`、`peers` 每轮间隔 5 秒尝试重连。无响应的会话采用 60 秒失活期限，恢复时间还包含重试和启动耗时。
- 中继握手仍验证两端公钥、网络、挑战值和签名；后续报文保持端到端加密与防重放。R 只能看到转发元数据和加密字节。
- 外层封装预留 98 字节，内层 UDP 报文上限 1102 字节，完整中继报文不超过 1200 字节，避免因双层加密与封装超出路径预算。
- 公网转发按源、目标分别限制速率，全局上限为配置速率的 4 倍；每个桶最多积累 1 秒额度，小包按至少 256 字节计费。`bytes-per-second` 默认 2 MiB/s，允许 1200 至 16 MiB/s。超额报文丢弃，由端到端可靠传输重试。
- 最多 8 个配置中继、32 个配置对端；沿用节点总连接数 100、发送和接收内存预算。转发不建立无界队列，也不支持多跳递归转发。
- 握手最多尝试 5 次，每次等待 1 秒；相同已认证请求在 10 秒内复用原响应，不重置已有会话密钥。分片最多重传 5 次，按分片独立计数并退避；发送和重组生命周期最多 30 秒。已完成记录保留 60 秒，单类最多 4096 条。
- 同步期间或 5 秒防抖窗口内收到的更高区块通知会保留，当前同步结束后继续处理；单次通知最多保留 60 秒，避免无效高度提示导致无限重试。

当前不会自动发现未知的内网节点公钥，也不依赖 UDP 打洞。将需要长期通信的节点身份明确放入配置即可。

## 本地验证

```powershell
mvn -B -ntp -o -s .mvn/settings.xml -Pci verify
```

`RelayNodeIT` 启动三个独立 JVM 和两个限制来源的 UDP 网关：拒绝内网节点之间的直达包，丢弃首次握手请求和响应，持续注入丢包、重复及乱序；检查双向大消息摘要、链同步和公网进程被强制终止后的自动恢复。结果及各节点日志写入 `target/relay-nodes-*/`。

这是本机受限网络模拟验证；实际公网部署还应按上面的接口检查真实防火墙、NAT 超时、链路 MTU 和可用吞吐量。

2026-09-09 验证结果：完整 `verify` 通过，116 个单元测试、18 个集成测试全部成功。最终三节点测试中，A → B 的 1 MiB 摘要探测用时 6061 ms，B → A 的 256 KiB 探测用时 7441 ms；两个网关分别注入 77 次丢包、114 次重复和 168 次延迟，观察到的最大加密 UDP 报文为 1200 字节。公网进程重启后，两端自动恢复并再次通过双向探测。这些耗时只描述该次故障注入测试，不代表真实公网性能。
